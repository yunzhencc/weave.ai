# 前端规范

修改组件、页面、主题或交互前阅读本文。目录职责见 [架构说明](architecture.md)，通用开发约定见 [AGENTS.md](../AGENTS.md)。

## 组件与逻辑

- 优先使用函数组件、现有 hooks 和 `src/ui/` 中的组件；基础组件采用当前 Base UI / shadcn 体系，动效组件沿用项目已有 beUI 实现，不引入另一套组件库解决已有能力。
- 页面路由负责参数和组装，业务界面放所属领域的 `ui/`。不要仅为拆文件增加 `Manager`、简单透传 props 或只返回另一个组件的包装层；实际承担布局、状态或行为的组件可以保留。
- 私有组件、hooks 和纯工具就近放置；多个页面或业务确实复用后再提取到共享位置。复杂组件按真实职责拆分，不把无关逻辑塞进一个组件，也不按行数机械拆分。
- 使用已有工具合并类名，图标优先使用 `lucide-react`。产品页面新增文案、提示和无障碍标签使用中文；代码标识符与供应商原始模型名不翻译。

## 状态与复用动作

- 局部状态留在组件或所属业务 hook 中；只有确实跨组件、跨页面共享时才使用已有共享入口。依赖中存在 Zustand 不代表所有状态都需要放进全局 store。
- 对已明确属于全局的状态、配置和动作，可以直接使用对应入口，避免无意义的多层透传；通用展示组件仍通过 props 接收业务数据和回调，不为减少 props 而绑定全局业务状态。
- 复制并提示、下载并提示等重复 UI 动作，按复用范围提取为 hook；只有需要共享或订阅的状态才进入 store。无 React 依赖的纯逻辑使用普通函数。
- TanStack Start 包含服务端渲染，不能把不同用户的请求状态放到服务端模块级单例中；浏览器 API 必须在浏览器执行阶段使用。
- `localStorage` 仅用于主题等少量简单配置，不存供应商密钥、图片、Base64 或生成任务历史。任务记录使用现有服务端存储；确有离线需求时再设计浏览器持久化，不预先指定新的存储依赖。

## 主题、样式与媒体

- 主题由 [根布局](../src/routes/__root.tsx)的 `ThemeProvider` 和 [全局样式](../src/styles.css)中的语义变量统一管理。优先使用 `bg-background`、`text-foreground`、`border-border` 等现有 token。
- 不为单个页面、按钮或弹层硬编码黑白、灰色背景来实现主题，也不在业务组件中重复写 `dark ? ...` 配色；确有差异时优先调整对应语义变量或共享组件样式。
- 组件私有样式使用 Tailwind `className` 或少量内联样式。全局 CSS 只放主题变量、基础重置、跨页面样式和必要的第三方覆盖，不堆页面私有规则。
- 新增按钮、弹窗和浮层沿用现有组件视觉风格。弹层也要跟随主题，不能只检查页面背景。
- 图片默认保留原始比例；裁剪、固定比例缩略图或自由变形必须符合明确的展示需求，不拉伸图片。生成进度、多图结果和工具栏避免占用不必要的空间。
- 保留键盘操作、可见焦点和图标按钮的可访问名称；动效尊重减少动态效果的系统设置。

## 验证边界

按改动验证浅色与深色主题、相关交互和必要的服务端渲染行为。自动化验证使用独立页面，不关闭用户已有标签页或服务。没有运行浏览器检查时，不把类型检查或构建通过描述为 UI 验收通过。
